# main 分支修复包 (2026-08-29)

针对 main 分支(daa61f8)代码审查发现的问题,三个文件已修复并通过全树语法检查 (22/22)。
**用法:在本地 main 分支上,把这三个文件复制到 `Project/Drone_F411/Core/Src/` 覆盖同名文件,提交即可。**

## 修复内容

### 1. rtos_app.c — 低压 printf 洪水 (致命) + ADC 测量降频
- **问题**: `SAFE_LOW_BATTERY` 是持续状态,原代码 200Hz 每拍 printf 一行 (~3.5ms/行 @115200),
  会把 5ms 节拍的控制任务整个拖死——恰好在最需要控制的时刻。
- **修复**: 边沿触发 (`lowBatPrinted` 锁存,电压恢复自动复位);打印内容带上实测电压。
- **附带**: 电池测量降频到 10Hz (`batDiv` 分频)。ADC 轮询是阻塞调用,200Hz 每测浪费 ~31µs,
  且 ADC 故障时最坏可把控制节拍拖住 80ms+。电压是慢变量,10Hz 足够。
  初始 `vbat=0` 安全: `Safety_Update` 对 `<=0.1V` 跳过低压检测。

### 2. safety.c — 五处持续状态 printf 洪水 (同类问题)
- ARM_FAIL / ATTITUDE_LIMIT / LOST_CONTROL / MOTOR_STALL / LOW_BATTERY 五个分支,
  原来在状态持续期间每拍 (200Hz) 打印一行,同样会拖死控制环。
- **修复**: 统一利用 `g_safety.status` 做边沿——只在"状态刚变成 X"那一拍打印;
  状态在函数尾部会被复位为 SAFE_OK,条件再次触发时会重新报告一次 (行为正确)。

### 3. battery.c — ADC 超时收紧 + 校准系数
- `PollForConversion` 超时 10ms → 2ms:正常单次转换 ~4µs 立即返回,超时只是故障兜底,
  8 次最坏阻塞从 80ms 降到 16ms (且调用方已降频到 10Hz)。
- 新增 `BAT_CALIB` 校准系数宏 (默认 1.000):若实测满电 4.20V 读出 4.05V,改成 4.20/4.05≈1.037。
  分压电阻 150K/100K 源阻抗 (~60kΩ) 偏高,读数可能系统性偏低,此宏留作软件校正入口。
